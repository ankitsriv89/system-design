Group Chat System

Project 15 · Real-Time & Product Systems

Architecture

  • WebSocket / STOMP — bidirectional real-time delivery via Spring's message broker
  • Kafka fanout — messages published to groupchat.messages, consumed and broadcast to all group subscribers
  • PostgreSQL — durable group, membership, and message history with Flyway migrations
  • Redis presence — TTL-based online/offline tracking per user
  • Group membership check — every send/join/read enforces server-side membership before any data is returned

Key Design Decisions

  • Messages are sequenced per group via MAX(seq)+1 — simple and correct for moderate scale
  • Fanout happens through Kafka so WebSocket nodes are decoupled — any node can receive and broadcast
  • STOMP topic per group: /topic/group/{id} — clients subscribe on join
  • JWT auth at REST boundary; STOMP principal propagated via Spring Security
