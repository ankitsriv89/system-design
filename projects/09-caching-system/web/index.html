Caching System

LRU · LFU · TTL · Stampede Protection

How It Works

A cache sits between your application and a slow data source (DB, API). It stores recent results in fast memory so repeated reads skip the expensive backend.

Cache-Aside Pattern
  1. App reads from cache → HIT: return value instantly.
  2. → MISS: load from source, write to cache, return.
  3. Writes go directly to the source; cache is invalidated or TTL expires.
LRU vs LFU Eviction

LRU (Least Recently Used) — evicts the key that hasn't been accessed for the longest time. Good for temporal locality; recently accessed keys stay warm.

LFU (Least Frequently Used) — evicts the key with the fewest total accesses. Better for skewed workloads where a few hot keys dominate.

Switch the policy via the ENV var EVICTION_POLICY=lfu.

TTL & Expiry

Every entry can carry a Time-To-Live. Two eviction paths:

  • Lazy expiry: checked on every GET — stale entries are evicted on access.
  • Active sweep: a background goroutine walks the map every 30 s and removes expired keys.
Stampede Protection

When a popular key expires, hundreds of requests may all miss simultaneously and race to reload the backend — a cache stampede.

This implementation uses singleflight.Group: only the first goroutine calls the loader; the rest wait and reuse the result. Trigger the demo below.

AOF Warm Restart

Every SET/DELETE is appended to an AOF (append-only file). On restart the log is replayed to restore the cache — expired entries are skipped automatically.
