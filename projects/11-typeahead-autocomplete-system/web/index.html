How It Works

Trie vs Redis Sorted Sets

A trie stores characters as tree nodes and walks them on each keystroke. Redis sorted sets take a different angle: every corpus item is inserted under all its prefixes as a member with its popularity as the score. ZREVRANGE ac:pfx:en:go 0 9 returns the top-10 items instantly — O(log N + K).

Ranking & Click Feedback

Each item carries a popularity float. When a user clicks a suggestion the backend calls IncrementPopularity, which raises the Redis score for all prefixes of that item in one pipeline — no rebuild needed. Scores decay only on full index rebuilds (controlled by the rebuild interval).

Hot Prefix Caching

Redis keys carry a 24-hour TTL. On a cache miss the handler falls back to a PostgreSQL LIKE prefix% query and back-fills Redis atomically. Popular prefixes never touch Postgres again within the TTL window.

Index Rebuild

A background goroutine rebuilds the full index every REBUILD_INTERVAL (default 30 min). It deletes all ac:pfx:* keys, then re-inserts every corpus item in 500-row batches — preventing stale entries from deleted items from persisting.

Performance Target
  • p50 suggest: < 2 ms (Redis hit)
  • p95 suggest: < 8 ms (Redis hit)
  • p99 suggest: < 25 ms (PG fallback)
  • Add item: < 20 ms
  • Full rebuild (10k items): < 5 s
