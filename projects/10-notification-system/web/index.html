How it works

A notification system decouples message acceptance from delivery. The API accepts a request synchronously, persists it, and enqueues a job. An async worker pool dispatches jobs to channel providers (email, SMS, push) with:

  • Template rendering — named templates with {{.Key}} placeholders
  • Preference checks — per-user opt-in/out and quiet hours (no sends during sleep)
  • Retry with backoff — up to 3 attempts with exponential delay (200 ms → 400 ms → 800 ms)
  • Dead-letter queue (DLQ) — exhausted retries land here; persisted to DB
  • Idempotency keys — duplicate requests with the same key are coalesced
