News Feed System

Project 16 · Real-Time & Product Systems

Architecture

  • Hybrid fanout — normal authors fan out on write into follower timelines; celebrities are pulled on read
  • Kafka pipeline — post.created events drive an async fanout worker, decoupling the write path from materialization
  • PostgreSQL — durable source of truth for posts and the follow graph
  • Redis sorted sets — one ZSET per user holds the materialized, ranked home timeline
  • Time-decay ranking — score = exp(−age / half-life); feed is ranked, not purely chronological

Key Design Decisions

  • Post is committed to Postgres before the Kafka event fires — never fan out a post that isn't durable
  • Celebrity threshold caps write amplification; their posts merge in at read time
  • Deletes are soft + honored lazily at read time, so a stale ZSET entry never surfaces a deleted post
  • Following someone backfills your timeline from their recent history
  • At-least-once Kafka is safe because fanout (ZADD) is idempotent
