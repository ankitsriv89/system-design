What is a Load Balancer?

A load balancer distributes incoming requests across a pool of backend servers so that no single server becomes a bottleneck. It sits between clients and backends, hiding the pool's composition.

Why it matters: single-server systems have a hard ceiling on throughput and availability. A load balancer lets you scale horizontally and route around failures transparently.

This implementation is an L7 (HTTP) load balancer with four algorithms, active health checks, connection draining, retry budgets, and live Prometheus metrics.

L4 vs L7 Load Balancing

L4 (transport layer): routes TCP/UDP streams by IP + port. Fast, protocol-agnostic, but cannot inspect content.

L7 (application layer): understands HTTP — can route by URL, headers, cookies, or body. Enables sticky sessions, canary deployments, and smarter health checks. This project is L7.

Health Checks & Failure Modes

Active probing: the balancer polls /healthz on every backend every 10 s. A 5xx or timeout marks the backend unhealthy and removes it from rotation.

Failure modes: backend flapping (rapid healthy↔unhealthy), retry storms (failed requests amplified), slow backends saturating connection pools.

Retry budget: each request is retried at most 2 times on 5xx. Retries are counted and alerted.
